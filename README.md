# SAPR-BAR Web

Основа независимой веб-версии SAPR-BAR для плоских стержневых конструкций. Приложение открывает, проверяет и сохраняет типизированную модель проекта и выполняет линейный статический расчёт рамными элементами Эйлера—Бернулли.

## Готовый контейнер на localhost

Нужны Docker Engine или Docker Desktop с Compose v2. Приложение не требует backend: многоэтапная сборка компилирует Vite-проект, после чего непривилегированный nginx раздаёт только статический `dist/`.

```bash
docker compose build
docker compose up -d
docker compose ps
```

Откройте <http://localhost:8080>. Проверка готовности: `curl -fsS http://localhost:8080/healthz`. Остановка: `docker compose down`.

Порт можно изменить без правки файлов:

```bash
SAPRBAR_PORT=8090 docker compose up -d
```

Публикация ограничена `127.0.0.1`: контейнер намеренно недоступен из локальной сети. Архив, `legacy-extract/`, `primer/`, документация, тестовые примеры, исходники и Node-зависимости не попадают в runtime-слой. Подробнее о выпуске, проверке состава и откате: [docs/deployment.md](docs/deployment.md).

## Требования для разработки

- Node.js 22 LTS или новее;
- npm 10 или новее;
- современный браузер.

Сервер приложений и база данных не нужны. Nginx в контейнере — только статический веб-сервер.

## Запуск

```bash
npm install
npm run dev
```

Vite выведет локальный адрес приложения. Встроенная портальная рама загружается автоматически.

## Работа в редакторе

Верхняя панель переключает выбор, создание узлов и элементов и перемещение вида. Колесо мыши меняет масштаб; координаты выбранного узла, свойства элемента, опоры и нагрузки редактируются справа. Сетка и привязка включаются отдельно, изменения поддерживают отмену и повтор.

После корректного расчёта в нижней области доступны таблицы перемещений, реакций и концевых усилий, а на схеме — деформированная форма и эпюры `N/Q/M`. Масштаб деформаций, единицы и правила знаков показаны рядом с результатами. После любого изменения модели старые результаты явно помечаются как неактуальные и не отображаются на схеме до повторного расчёта.

Кнопка «Редактор CN/LD/MD» открывает три текстовых редактора. Можно загрузить, создать с нуля или из синтетического B/R-примера, изменить и отдельно скачать каждый файл. Импорт понимает подтверждённое оформление настоящего B-комплекта: служебные `*`-строки, метки `=NN`, пустые резервные записи и CRLF; вход декодируется как CP866. Проверка всего комплекта требует выбрать вариант HELP_30B/R и исходную систему единиц, затем показывает отчёт до применения. Неподдерживаемые воздействия не игнорируются. После применения исходные тексты сохраняются в JSON и вновь открываются в legacy-редакторе.

Кнопка «Печать» формирует браузерный печатный отчёт со схемой, исходными данными, нагрузками, допущениями, актуальными результатами и версией ядра. Сохранение современного проекта остаётся основным способом обмена данными.

## Сборка и проверки

```bash
npm run typecheck
npm test
npm run build
```

Все проверки одной командой:

```bash
npm run check
```

Статическая production-сборка создаётся в `dist/`. Её можно разместить на любом статическом хостинге.

## Проверенные возможности

- типизированное открытие, валидация и сохранение `.saprbar.json` версии `1.0.0`;
- создание и редактирование плоской стержневой схемы, опор, концевых шарниров, материалов, сечений и реализованных нагрузок;
- настоящий линейно-статический расчёт рам Эйлера—Бернулли, реакции, перемещения, `N/Q/M`, напряжения и деформированная схема;
- явный отказ для механизмов, сингулярных и несовместимых моделей;
- пометка результатов как неактуальных после изменения модели;
- создание, текстовое редактирование, проверка и скачивание CN/LD/MD в документированном синтетическом профиле, предварительный отчёт импорта и печатный отчёт.

Математическое ядро покрыто аналитическими unit-тестами; типы, тесты и production-сборка запускаются `npm run check`. Фактические результаты текущего прогона и ограничения браузерной проверки зафиксированы в [docs/status.md](docs/status.md).

## Формат проекта

Проект сохраняется в UTF-8 JSON с рекомендуемым расширением `.saprbar.json`. Текущая версия схемы — `1.0.0`; значения расчётной модели хранятся в SI. При открытии приложение сначала проверяет структуру, версию, числа, ссылки и совместимость поддерживаемого подмножества. Ошибочный файл не заменяет открытую модель.

Пример: [examples/portal-frame.saprbar.json](examples/portal-frame.saprbar.json).

Основные типы находятся в `src/model/types.ts`, семантическая проверка — в `src/model/validation.ts`, безопасное чтение/запись — в `src/model/projectFormat.ts`. Эти модули не зависят от React.

## Поддерживаемая модель данных

- двумерные узлы;
- рамные стержни с материалом, сечением и концевыми освобождениями вращения;
- материалы с модулем Юнга;
- сечения с `A`, `Iz`, `y−`, `y+` и исходной геометрией;
- закрепления `Ux`, `Uy`, `Rz`;
- узловые `Fx`, `Fy`, `Mz`;
- равномерные стержневые нагрузки `qx`, `qy` в локальных осях;
- одно линейно-статическое загружение и параметры будущего решателя.

Подробные границы приведены в [docs/spec.md](docs/spec.md), текущий статус — в [docs/status.md](docs/status.md).

## Расчётное ядро и ограничения

Реализованы сборка глобальной системы, нулевые закрепления, концевые освобождения вращения, узловые и равномерные локальные нагрузки, перемещения, реакции и внутренние `N/Q/M` с нормальными напряжениями. Механизм или численная вырожденность возвращают явный отказ.

Математика и знаки описаны в [docs/solver-theory.md](docs/solver-theory.md), аналитические проверки — в [docs/solver-verification.md](docs/solver-verification.md). Совместимость с вычислительным алгоритмом DOS SAPR-BAR не заявляется.

Не поддерживаются геометрическая/физическая нелинейность, устойчивость, собственные и вынужденные колебания, динамика, комбинации загружений, температура, собственный вес, пружины и заданные перемещения. Импорт B проверен на настоящем комплекте `GOLOBORO.CN/LD/MD`, рассчитанном SAPR-BAR 3.0. Скачивание текста пока не подтверждает обратное чтение DOS-программой: экспорт CP866 и точное воспроизведение шаблонов не верифицированы. Вариант R проверен только синтетически. Автоматический legacy-экспорт современной графической модели отсутствует.
